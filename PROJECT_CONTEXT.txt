# PROJECT CONTEXT – Leefstijlplanner

## Productnaam

**Leefstijlplanner**
**Van registratie naar regie**

Voorheen heette dit project intern “VoedingsManager” / “VoedingsApp”. De technische projectmap mag voorlopig `VoedingsApp-v10` blijven, maar de productnaam is vanaf nu **Leefstijlplanner**.

---

## Missie

Leefstijlplanner is ontstaan vanuit de praktijk van leven zonder alvleesklier, volledige insulineafhankelijkheid, Creon-gebruik, voeding, sport, supplementen en dagelijks gezondheidsmanagement.

De app is geen gewone voedingsapp.

De kernfilosofie is:

Registratie
↓
Analyse
↓
Inzicht
↓
Planning
↓
Regie

Registratie levert gegevens.
Analyse ontdekt patronen.
Inzicht verklaart waarom iets gebeurt.
Planning maakt vooruitkijken mogelijk.
Regie maakt actief sturen mogelijk op gezondheid, prestaties, herstel en kwaliteit van leven.

## DailyLog structuur

`dailyLog` is een array van dag-objecten.

Een dag-object bevat o.a.:

```js
{
  date,
  meals: [],
  insulinEvents: [],
  glucoseEvents: [],
  glucoseBoostEvents: [],
  movementEvents: [],
  supplementEvents: [],
  bowelEvents: [],
  noteEvents: [],
  trainingPlanEvents: [],
  sportSupplementPlanEvents: []
}
```

Belangrijk: nieuwe day-objecten moeten altijd via `createEmptyDay(date)` of een vergelijkbare helper worden aangemaakt, zodat arrays niet ontbreken.

## Planner-richting

Belangrijk inzicht: trainingen en vaste supplementmomenten zijn geen gewone tijdlijn-events, maar planner-items.

De planner moet weken vooruit kunnen kijken.

Voorbeelden:

* maandag 10:00 borst
* woensdag 10:00 schouders
* vrijdag 10:00 benen
* dagelijks 09:00 chlorella
* dagelijks vitamine D
* supplementen rondom training
* vakantie/weekend meenemen in planning

De planner moet uiteindelijk kunnen tonen:

* vandaag
* morgen
* deze week
* volgende week
* langere periode vooruit

Planner-items krijgen later waarschijnlijk eigenschappen zoals:

```js
{
  id,
  date,
  time,
  title,
  type,
  status,
  repeat,
  note
}
```

Status kan later bijvoorbeeld zijn:

* planned
* done
* skipped
* moved

## Werkwijze

De gebruiker is geen ervaren programmeur.

Daarom altijd:

* stap voor stap werken
* exact aangeven welk bestand
* exact aangeven waar code moet komen
* zo min mogelijk tegelijk aanpassen
* eerst stabiliteit, daarna uitbreiding
* geen grote herschrijvingen zonder noodzaak
* bij twijfel eerst bestand uploaden of relevante code tonen
* liever kleine veilige stappen met build/test ertussen

---

## Belangrijke afspraak

Bij grotere codewijzigingen liever:

* Codex gebruiken in VS Code
* of volledige bestanden gecontroleerd vervangen
* niet eindeloos losse haakjes/regels plakken

ChatGPT-downloadlinks werken soms onbetrouwbaar. Daarom liever code als plakbaar codeblok of Codex direct in VS Code gebruiken.
